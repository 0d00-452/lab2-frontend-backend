## 0. 先背这张图（实验二版）

比实验一多了一个"关卡"，就在中间：

```
浏览器
  │
┌─────────────────────────────── 前端工程（localhost:5173）───────────────────────────────┐
│                                                                                        │
│  Vue 组件（UserForm / UserTable / App）                                                 │
│     │  ① 用户点了按钮，组件里的方法被调用                                                  │
│     ▼                                                                                  │
│  js/api.js 的 UserApi（接口清单）                                                        │
│     │  ② 统一从这里调接口，不散落在各组件里                                                  │
│     ▼                                                                                  │
│  axios 实例 + 拦截器                                                                     │
│     │  ③ 请求拦截器：打日志、加 token；响应拦截器：剥壳、翻译错误                               │
│     ▼                                                                                  │
└────────────────────────────────────────────────────────────────────────────────────────┘
     │  ④ fetch → HTTP 请求
     ▼
╔══════════════════════════════════════════════════════════════════════════════════════╗
║  ★ 跨域关卡（CORS）                                                                    ║
║   页面在 5173，接口在 8081 → 端口不同 = 跨域                                             ║
║   浏览器先发 OPTIONS 预检 → 后端 WebConfig 说"允许" → 浏览器才放行真正的请求                ║
║   如果后端没表态 → 浏览器扣下响应，控制台报 CORS policy 错误                                 ║
╚══════════════════════════════════════════════════════════════════════════════════════╝
     │  ⑤ 通过关卡后，请求才真正到达后端
     ▼
┌─────────────────────────────── 后端工程（localhost:8081）──────────────────────────────┐
│  Controller（@RestController，只返回 JSON）→ Service → Mapper → 数据库                  │
│     │  ⑥ 成功 200/201；出错 400/404/409 + 统一响应体                                     │
└────────────────────────────────────────────────────────────────────────────────────────┘
     │  ⑦ 响应原路返回，再过关卡（响应头要带 Access-Control-Allow-Origin）
     ▼
前端拦截器剥壳 → 组件更新界面
```

**一句话版本**：
> **组件调接口，接口过拦截器，拦截器发出请求，请求先过跨域关卡，才到后端；回来的路同样要过关卡。**

## 2. 五天上手计划

- **做**：**只关掉前端的窗口**，刷新浏览器 → 页面打不开了；再只关后端 → 页面能打开但显示"连不上后端"。

### Day 2｜亲眼看见跨域（★ 最重要的一天）
- **做**：F12 → Network → 点一次【新增】→ 找到 `OPTIONS` 和 `POST` 两条，看响应头里的 `access-control-allow-origin`。

- **完成标志**：能画出"浏览器 → 预检 → 后端允许 → 真正的请求"这条链路。

### Day 3｜Vue 组件
- **做**：按 `App.js → UserForm.js → UserTable.js` 的顺序读一遍，标出每个组件的「数据、模板、行为」。

## 3. 抽测最可能被问的 12 个问题

| # | 老师可能问 | 你答（要点） |
|---|---|---|
| 1 | 前后端分离是什么意思？ | 前端和后端是两个独立运行、独立部署的进程，之间只通过 HTTP 接口通信 |
| 2 | 你的前端跑在哪、后端跑在哪？ | 前端 5173（Node 静态服务器），后端 8081（Spring Boot） |
| 3 | 什么是跨域？为什么会有跨域？ | 页面的源和接口的源（协议/域名/端口）不一致；浏览器出于安全有同源策略 |
| 4 | 跨域限制是谁造成的？ | 浏览器。请求其实发出去了、后端也处理了，是浏览器不让页面读响应 |
| 5 | 你是怎么解决跨域的？ | 后端配 CORS（`WebConfig implements WebMvcConfigurer`，`addCorsMappings`），响应头返回 `Access-Control-Allow-Origin` |
| 6 | 预检请求是什么？为什么会有？ | 非简单请求（如 `Content-Type: application/json` 的 POST）发出前，浏览器先自动发一个 OPTIONS 询问后端是否允许 |
| 7 | `allowedOrigins` 能写 `*` 吗？ | 开了 `allowCredentials(true)` 就不能写 `*`，规范禁止；而且写 `*` 等于对全网开放，不安全 |
| 8 | `@RestController` 和 `@Controller` 什么区别？ | `@RestController = @Controller + @ResponseBody`，返回值直接转 JSON 写入响应体，不返回页面 |
| 9 | 你的接口为什么返回 201 而不是 200？ | RESTful 规范：新增资源成功用 201 Created，并在 Location 头给出新资源地址 |
| 10 | 前端组件之间怎么传数据？ | 数据用 props 往下传，事件用 emit 往上报（单向数据流） |
| 11 | Axios 拦截器是干什么的？ | 在请求发出前/响应回来后统一插一脚：加 token、打日志、全局 loading、统一处理 401 等 |
| 12 | 你的 axios 是官方的吗？ | **不是**。本机完全离线装不了官方 axios，用自研的兼容层（API 形状一致），换回官方只改一行 script 标签 |

> 第 12 题一定要**主动、如实**回答。课程明确要求 AI 使用与替代方案要留痕，
> 藏着不说反而在追问时被动 —— 而且你的 `docs/AI生成内容核对记录.md` 里已经写清楚了。

## 4. 三个自测动作

### 动作 1：合上代码画出「跨域关卡」那张图
白纸画出：组件 → api.js → 拦截器 → **跨域关卡（预检/Allow-Origin）** → 后端 → 原路返回。
画不出关卡在哪，就是还没懂跨域。

### 动作 2：自己加一个完整功能（最能证明实力的一个）
**任务**：给用户加一个 `status` 字段（1=启用，0=禁用），前端能筛选"只看启用的"。

要改的地方（前后端都要动，按顺序）：
1. `backend/.../db/schema.sql`：加一列 `status TINYINT NOT NULL DEFAULT 1`
2. `backend/.../db/data.sql`：初始数据给上值
3. `backend/.../entity/User.java`：加字段 + getter/setter
4. `backend/.../mapper/UserMapper.xml`：查询 SQL 里加上条件
5. `backend/.../service/UserService.java`、`controller/UserController.java`：透传参数
6. `frontend/js/api.js`：`UserApi.list` 加上新参数
7. `frontend/js/components/App.js`：加一个下拉框，选中后重新查询
8. `frontend/js/components/UserTable.js`：表格加一列显示状态
9. `docs/openapi.yaml`：把新字段和新参数补进文档（**这一步最容易漏，但课程要求了**）

**能独立走完这 9 步，实验二就真的过关了。**这也是实验报告里最真实的素材。

### 动作 3：故意制造 3 个错误并修好

| 制造的错 | 应该出现的现象 | 你要能说出原因 |
|---|---|---|
| 注释掉后端 CORS 配置 | 控制台报 `blocked by CORS policy` | 浏览器同源策略拦截，后端没表态允许 |
| 把 `allowedOrigins` 里的端口改成 5174 | 后端返回 403 `Invalid CORS request` | 请求的 Origin 不在白名单里 |
| 把拦截器成功判断改成 `status === 200` | 新增成功了却提示失败 | 新增返回的是 201，必须判断 2xx 区间 |
