## 二、核对方法（怎么"核对"才算数）

**不能只看代码"觉得对"，要拿真实请求去撞。** 本项目用了三种手段：

| 手段 | 核对什么 | 命令/位置 |
|---|---|---|
| 直接打接口，看 HTTP 状态码 | 错误边界（400/404/409）对不对 | `Invoke-WebRequest` 带 `Origin` 头逐条调用（见第五节实测结果） |
| 让前端代码真实跑一遍 | 前端拿到响应后能不能正确处理 | 把 `axios-lite.js` + `api.js` 加载到 Node 里，真实请求后端 |
| 浏览器 F12 → Network | 预检请求与响应头是否真的存在 | 手动点一次新增，看 `OPTIONS` 与 `Access-Control-Allow-Origin` |

> 第 2 条有点特别：因为 `axios-lite.js` 底层用的是 `fetch`，
> 而 Node 18+ 也自带 `fetch`，所以**同一份前端代码在 Node 里也能跑**。
> 这样就能在不开浏览器的情况下，验证「接口地址、参数拼装、拦截器、错误处理」是不是真的对。

## 三、核对中发现并修正的问题（★ 这部分最有价值）

### 问题 1：`allowedOrigins` 写成了 `*`，但同时又开了 `allowCredentials`

- **AI 初稿**：`.allowedOrigins("*").allowCredentials(true)`
- **后果**：Spring 启动即抛异常 —— 规范明确禁止「允许携带凭证」时用通配符 `*`，
  否则等于把用户 Cookie 暴露给任何网站。
- **修正**：改成具体地址 `"http://localhost:5173", "http://127.0.0.1:5173"`。
- **教训**：`*` 看着方便，但它和 `allowCredentials` 是互斥的。这是 CORS 最经典的坑。

### 问题 2：前端拦截器用 `status === 200` 判断成功 —— 会把 201 当成失败

- **AI 初稿**：`if (res.status === 200) { 成功 } else { 失败 }`
- **后果**：新增接口返回的是 **201 Created**（RESTful 规范），
  按这个写法，**新增成功了前端却提示失败**。
- **修正**：`if (res.status >= 200 && res.status < 300)`。
- **实测证据**：`POST /api/users` → `HTTP 201`，`Location: /api/users/5`。
- **教训**：只要是 RESTful 接口，**不要拿某一个具体状态码判断成功，要判断 2xx 区间**。

### 问题 3：OpenAPI 文档把 `password` 写成了普通响应字段

- **AI 初稿**：`User` schema 里 `password` 是普通 string 字段。
- **核对代码**：`UserController.hidePassword()` 在返回前会把密码置空。
- **修正**：在文档里明确标注 `password: nullable: true`，并注明"响应中始终为 null；
  真实项目应改用不含该字段的 VO 类型"。
- **教训**：**文档字段必须对着代码核对**，不能照着数据库表抄 —— 表里有，不代表接口会返回。

### 问题 4：漏了 `deleted` 字段

- **AI 初稿**：`User` schema 里没有 `deleted`。
- **核对**：实体类、表结构里都有，而且接口确实会返回它（值恒为 0，因为查询带了 `deleted = 0`）。
- **修正**：补上该字段并写明含义。

### 问题 5：时间字段只写了 `format: date-time`，没写实际格式

- **核对**：实际返回 `2026-10-14T21:07:14.123`（带微秒的 ISO 格式）。
- **影响**：前端直接显示会很难看，`UserTable.formatTime()` 里做了裁剪。
- **修正**：文档补上 `example`，前端补上格式化方法。

### 问题 6：删除成功后端返回 200 而不是 204（需要文档说清）

- **核对**：按 HTTP 规范，"删除成功且无内容返回"应当用 `204 No Content`。
  本项目用 `200 + 响应体`（返回剩余用户数），是为了让前端统一处理。
- **结论**：两种都合理，**但必须在文档里写清楚**，否则联调时前端会以为接口写错了。

### 问题 7：错误边界只做了「弹一个框」，没有按状态码分流

- **AI 初稿**：`catch (e) { alert('操作失败') }`
- **问题**：用户看到这句话完全不知道该怎么办 —— 是输入错了？还是系统挂了？
- **修正后的分流（这才是"错误边界"该有的样子）**：

| HTTP 状态码 | 业务码 | 含义 | 前端应该怎么做 | 本项目实现 |
|---|---|---|---|---|
| 400 | 10001 | 参数不合法 | 提示在**表单旁边**，让用户改输入 | `UserForm` 的 `error` 显示在表单下方 |
| 404 | 30003 | 资源不存在 | 提示 + **刷新列表**（数据已经变了） | `App.remove()` catch 后 `load()` |
| 409 | 30002 | 用户名冲突 | 提示 + 让用户**换个用户名** | `UserForm` 显示后端返回的原话 |
| 500 | 50000 | 服务端异常 | 提示"系统繁忙，请稍后再试" | 后端只返回笼统文案，堆栈只进日志 |
| 网络错误 | — | 后端没启动 | 提示"后端还开着吗？" | `axios-lite` 的 catch 分支 |
| 超时 | — | 超过 8 秒 | 提示超时，可重试 | `AbortController` 实现 |

> 这张表建议直接抄进你的实验报告 —— 它就是课程说的「错误边界」的答案。

### 问题 8：本机离线导致的两个「非标准替换」（必须如实说明）

| 项 | 标准做法 | 本项目做法 | 原因与影响 |
|---|---|---|---|
| HTTP 客户端 | 官方 `axios` | `lib/axios-lite.js`（自研兼容层） | 本机完全离线，npm 源与所有 CDN 均不可达。用法与官方 Axios 一致，**换回去只改一行 script 标签**。未实现取消令牌、上传进度等能力 |
| Vue 来源 | `npm install vue` 或 CDN | `lib/vue.global.prod.js`（Vue 3.4.27 完整构建版） | 同上。取自本机 WPS Office 自带的资源目录，MIT 许可，已验证 API 完整（含模板编译器） |

## 四、我没有让 AI 决定的部分（边界意识）

| 事项 | 为什么必须人工定 |
|---|---|
| **允许哪些源跨域** | 这是安全边界。写成 `*` 等于对全网开放，属于责任问题，不能让 AI 拍板 |
| **HTTP 状态码怎么用** | 一旦定下来，前后端都要跟着它走，属于接口契约 |
| **密码等敏感字段是否返回** | 涉及隐私与合规，必须人工确认 |
| **错误提示的文案** | 要直接给用户看，语气与信息量由人决定 |
